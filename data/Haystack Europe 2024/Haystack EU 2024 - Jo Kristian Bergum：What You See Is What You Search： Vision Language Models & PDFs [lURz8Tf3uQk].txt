How many of you have tried to index PDFs? Quite a few, okay. This is quite a challenge. PDFs can be complex, with visual infographics, tables, charts, images, etc. When chatbots like ChatGPT started, interacting with PDFs was a primary use case because a lot of information in the world is within these PDFs. Historically, we used text extraction, then chunk text embedding, and so on. However, extracting text from these documents is tricky. Elements in PDFs might be embedded images, making text non-extractable. You might see text visually but not retrieve it during a search because it’s not extracted as text data. Managers might say they see the text, why can’t the search engine retrieve it? It's frustrating to explain that it's an embeddable image, and that makes a huge difference.

This is where Vision Language Models come into play. These models allow us to bypass some of those text extraction challenges by embedding the entire PDF page. Using models like ColPali, which stands for 'col polygamma', we can utilize this multi-vector embedding effectively for retrieval. Traditionally, we used pipelines that included text extraction and complex processing steps. With ColPali, we simplify this by embedding each PDF page and generating multi-vector representations. This process provides better relevancy compared to traditional methods, which often involve complex preprocessing steps. I see ColPali as the future direction for document retrieval. It tackles complex formats and increases the universality for different types of file formats beyond text extractions, offering a broader support for diverse real-world documents found in the industry.

Now, on to a quick primer about Vision Language Models (VLMs). These are multimodal models that learn from images and text simultaneously. They've become quite powerful over the year. Initially, they were used for fun things like identifying cat breeds in images. However, their potential extends far beyond that. For instance, the model Polygamma offers significant capabilities for OCR and embedding. It can answer complex questions by reading just the visual elements in a PDF, which is particularly beneficial for document retrieval.

The researchers behind ColPali wondered if VLM capabilities could be extended from just understanding and answering questions about images to actually offering advanced and efficient document retrieval. Imagine searching through 100,000 PDFs efficiently without any preliminary text extraction. The goal is to streamline retrieval in real industrial settings where datasets aren't preprocessed like in some benchmarks. ColPali manages this by using contextualized embeddings based on VLMs, replacing steps like OCR and layout detection with a single step model embedding from a screenshot.

**Audience Member:**  
In real-world applications, how practical is it to use ColPali? For instance, how long does it take to generate embeddings per page?

**Jo Kristian:**  
Excellent question. On an M1 laptop, document-side inference runs for about 2.5 seconds per page. On the query side, the embedding process takes under 100 milliseconds with an M1 chip. One benefit of Vespa is efficient data retrieval and matching due to minimal vector data movement across networks, which scales well.

**Audience Member:**  
If handling a less complex PDF with mostly text, will ColPali outperform something simpler like ColBERT?

**Jo Kristian:**  
Great question. For text-heavy subsets, traditional methods like bm25 or ColBERT may perform comparably. While ColPali has the advantage across varied document types, if your data is structured and predominantly textual, traditional methods suffice. However, for complex documents like HTML or MS Word, ColPali's integration scope excels because it merges product title, descriptions, and images into joint representations, appealing especially for e-commerce scenarios.

**Audience Member:**  
Thanks for the talk, Jo. Regarding explainability, can ColPali identify what page elements are most relevant to user queries?

**Jo Kristian:**  
Yes, absolutely. MaxSim provides insight by highlighting patches most similar to query vectors. This feature offers interpretability by allowing you to identify which parts of a document are causing high relevance scores, contrasting the singular outputs of single vector models.
