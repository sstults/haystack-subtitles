The importance of UBI lies in the fact that in the database world, a good result is well-defined, which is not the case in the search world. Everyone wants the best result, but "best" is very subjective and varies for different stakeholders. The end targets, however, should be the users. By capturing user behaviors, we should infer what is good and improve search strategies accordingly.

UBI's goals include collecting data such as search interactions, queries, and result engagements. This data is owned by you, not given to anyone else. UBI helps identify anomalies, optimize user interactions, and refine search relevance over time.

Although there are tools like Google Analytics, Core Metrics, or Snowplow, they often provide generic data that requires cleaning before use by search engineers. UBI, however, is tailored exclusively to the needs of search engineers, making it more precise and relevant.

UBI with OpenSearch involves installing a plugin to collect and analyze search data efficiently. At its core, UBI provides a standardized schema, client-side instrumentation, tools to collect the generated data, and means to analyze this data.

Looking at the technical details, UBI in OpenSearch is represented by two indices: the Queries Index and the Events Index. The Queries Index logs search queries, while the Events Index captures user interactions like clicks.

For example, here's the standardized schema for the Queries Index:
- ClientID identifies the user.
- Query captures the entire OpenSearch DSL query.
- Query Attributes are a flat object for extended metadata.
- QueryID is crucial for tracking the search journey.
- ResponseID logs docIDs sent to users.
- User Query records the search term used.

Similarly, the Events Index records metrics like Action Name, Application, ClientID, and Event Attributes, which contain detailed information about user interactions such as search result positions and dwell time.

To implement UBI with OpenSearch, we need to install the plugin. The data flow consists of users performing searches, and their actions being logged by UBI. For example, search requests are logged, and user interactions with facets or clicks on search results are recorded.

In a demonstration using the OpenSearch dashboards, we can see how search queries and events are collected and stored. By executing a search query with UBI, we can view documented details like query IDs and search results. For event logging, client-side instrumentation is used to capture interactions like product clicks or filter usage.

With a fully populated UBI schema, we can create dashboards to analyze the data for insights. We can visualize actions performed, click positions, profit margins, popular searches, session durations, and spending patterns. These insights are readily available for download and use in OpenSearch dashboards. By using standardized schema, you can also benefit from dashboards developed by others within the open-source community.

Additionally, OpenSearch allows the use of SQL for ad-hoc querying and analysis, making it accessible to various stakeholders. Sample queries for longtail searches, trending searches, and user sessions can provide valuable insights.

In terms of possibilities, leveraging the data for machine learning and model training becomes feasible. You can use various AWS services and open-source software with exported data from OpenSearch. UBI provides the necessary click metrics required for optimization and learning-to-rank approaches.

UBI with OpenSearch encourages using anomaly detection to identify trending searches or anomalies in your search data. It's essential to implement efficient strategies for managing data growth, like using rollup indices to summarize older data and cut costs.

Although UBI is currently available with OpenSearch, it can be adapted for other search engines in the future. External frameworks can support non-OpenSearch queries, with the events index being usable irrespective of your choice of search engine.

Finally, we're working on an RFC to further enhance UBI by automating implicit judgments and creating search metrics. This will enhance the search optimization process. If you're interested in contributing or have suggestions, we're open to collaboration.
